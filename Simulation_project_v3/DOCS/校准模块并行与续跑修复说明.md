## 1. 修复背景与目标
本次修复针对参数校准流程中的 4 个已确认问题：

1. `differential_evolution` 分支未正确使用 `initial_values`（断点恢复初值不生效）。
2. 历史文件命名与续跑读取不一致（并行写 PID 文件，但恢复只读固定文件名）。
3. 默认并行配置下 checkpoint 回调被禁用（断点续跑能力弱化）。
4. `verify_calibration_config.py` 在 Windows 默认编码环境可能报 `UnicodeEncodeError`。

目标是保证：
- 并行与串行路径下，初值、历史、断点与续跑行为一致且可复现。
- Windows 常见终端环境下验证脚本可直接运行。

## 3. 关键修复内容

### 3.1 修复点一：DE 分支显式使用 `x0`
- 在 `differential_evolution(...)` 调用中显式传入 `x0=initial_values`。
- 断点恢复时，`best_params`/`current_params` 会作为下一次优化起点，保证恢复语义成立。

### 3.2 修复点二：历史文件读写一致化
- 新增历史文件收集与合并流程：
  - `_list_history_files()`
  - `_consolidate_history_files()`
- 续跑时优先读取合并后的 `calibration_history.csv`，兼容并行 PID 历史文件。
- 并行场景下补充“最优评估回填”：
  - `_get_best_eval_from_history_files()`
  - 保证 checkpoint 可写入有效 `best_params/best_obj_value`。

### 3.3 修复点三：并行模式 checkpoint 可用
- 并行 DE 不再禁用回调，启用 `de_callback` 定期保存 checkpoint。
- 优化结束后额外保存一次最终 checkpoint，保障“至少有一个可恢复入口”。

### 3.4 修复点四：Windows 编码兼容
- 将 `verify_calibration_config.py` 中的 `✓/✗/⚠️/✅` 替换为 ASCII 标记：
  - `[OK] / [ERR] / [WARN]`
- 规避 GBK 终端编码下的字符输出异常。

### 3.5 并行历史落盘稳健性增强（补充）
- 在 PID 历史模式下，目标函数对象在 worker 端可能频繁重建，`n_evaluations` 可能重复从 1 开始。
- 对应策略：
  - PID 历史模式强制 `history_save_interval = 1`。
  - PID 历史采用“单条追加写入（append）”，避免覆盖与漏写。

## 4. I/O 行为说明（修复后）

### 4.1 输入
- `CONFIG/calibration_config.yaml`：
  - `optimization.method = differential_evolution`
  - `optimization.options.workers`（`>1` 进入并行）
  - `checkpoint.enabled/auto_resume/save_frequency`

### 4.2 输出
- 串行模式：
  - `OUTPUT/calibration/calibration_history.csv`
  - `OUTPUT/calibration/checkpoint_latest.pkl`
- 并行模式：
  - `OUTPUT/calibration/calibration_history_<pid>.csv`（每个 worker）
  - `OUTPUT/calibration/calibration_history.csv`（合并后统一历史）
  - `OUTPUT/calibration/checkpoint_latest.pkl`
