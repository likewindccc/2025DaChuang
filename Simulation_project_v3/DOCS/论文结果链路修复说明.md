# 论文结果链路修复说明

## 文档目的

本文档说明 2026-03-12 对论文模拟链路所做的关键修复，重点覆盖以下文件：

- `run_paper_simulation.py`
- `MODULES/SIMULATOR/market_simulator.py`
- `MODULES/MFG/equilibrium_solver.py`
- `MODULES/MFG/bellman_solver.py`

这些修复的目标是统一论文表格口径、消除政策场景间的抽样噪声污染，并修正 `a_optimal` 的经济含义与输出口径。

## 上下游关系

### 上游依赖

- `CONFIG/mfg_config.yaml`：MFG 基准配置来源。
- `CONFIG/simulator_config.yaml`：政策场景定义来源。
- `CONFIG/target_moments.yaml`：目标矩定义来源。
- `MODULES/CALIBRATION/target_moments.py`：正式的模拟矩计算口径。
- `MODULES/POPULATION`：基础人口样本采样来源。

### 下游输出

- `OUTPUT/mfg/`：基准均衡个体、策略、历史轨迹。
- `OUTPUT/simulation/`：政策场景详细结果与比较表。
- `OUTPUT/paper_tables/`：论文表格所需结构化数据。

## 修复内容概览

### 1. 统一论文运行配置来源

`run_paper_simulation.py` 现在会先创建一份论文运行专用临时配置，再由基准均衡和政策模拟共同复用该配置。这样可以保证：

- 基准与政策实验使用同一组 `n_individuals=10000`、`max_outer_iter=200`。
- 不再直接覆写正式的 `CONFIG/mfg_config.yaml`。
- 论文运行结束后自动清理临时配置文件。

### 2. 固定政策场景基础人口样本

`run_paper_simulation.py` 新增共享基础人口样本创建逻辑。`MarketSimulator.run_batch()` 与 `run_scenario()` 新增：

- `base_population`
- `initial_T`

两个入参，全部政策场景会复用同一底层人口抽样，仅保留政策参数冲击本身的差异。

### 3. 修复“固定样本后培训政策失效”的问题

`EquilibriumSolver.initialize_population()` 现在会在“外部传入基础样本”的情况下，继续对样本副本施加 `population_adjustment`。这保证了：

- 共享样本机制成立。
- 培训类政策对 `S`、`D` 的冲击不会因为复用样本而被绕开。

### 4. 论文导表复用正式矩口径

`run_paper_simulation.py` 的 `_export_moment_comparison_table()` 已改为直接调用 `TargetMoments.get_moment_comparison()`。修复后：

- `mean_weekly_hours` 改为就业者口径。
- `std_weekly_hours` 改为就业者口径。
- `job_finding_rate` 与 `separation_rate` 改为读取求解器正式输出，不再手写 `0.05` 近似。

### 5. 修复 `a_optimal` 的输出口径

修复分两层：

- `BellmanSolver.solve()` 中，当前已就业个体的反事实搜索努力在导出前置为 `0.0`。
- `EquilibriumSolver._save_equilibrium()` 中，再按最终保存时点的就业状态对 `a_optimal` 做一次对齐，防止“上一期失业、下一期就业”的个体在最终文件里仍保留非零努力值。

这能避免论文表格和可视化把就业者误解释为仍在进行正搜索努力。

### 6. 政策主表增加收敛筛选

`_export_policy_effects_table()` 现在会：

- 单独导出全量结果：`table_6_2_policy_effects_all_runs.csv`
- 主表 `table_6_2_policy_effects.csv` 优先保留已收敛场景
- 若缺少已收敛的基准场景，则保留诊断信息但不计算政策增量

这样可以避免未收敛结果直接进入论文主结论。

### 7. 低优先级稳健性加固

本轮还补了三条低优先级但实用的保护：

- `MarketSimulator._build_mfg_config()` 会显式把 `paths.output_dir` 锁定到项目固定的 `OUTPUT/mfg`，避免外部配置改动后误读历史残留结果。
- `run_sensitivity_analysis()` 明确注明当前是“有意不复用共享样本”的独立扰动实验，降低后续误解风险。
- `_export_calibration_params_table()` 在发现 `success=false` 时会输出警告，提醒当前导出的只是参数快照，而不是已成功收敛的最终校准。

### 8. 基准策略快照单独保存

论文脚本在阶段一结束后，会立即把基准均衡对应的 `equilibrium_policy.csv`
 读入内存，并额外保存为：

- `OUTPUT/paper_tables/baseline_equilibrium_policy.csv`

这样阶段四导出表 5.2 时，会直接使用这份基准快照，而不是再去读取可能已经被后续政策场景覆盖的 `OUTPUT/mfg/equilibrium_policy.csv`。

### 9. history 与最终统计统一到演化后口径

`EquilibriumSolver.solve()` 的 `history["unemployment_rate"]` 与 `diff_u`
 现在统一按 `KFE evolve()` 之后的失业率记录。这样：

- `equilibrium_history.csv` 的尾行失业率
- `final_statistics["unemployment_rate"]`
- `final_unemployment_rate`

三者会使用同一时间点口径，便于后续绘图、收敛诊断和论文表格互相核对。

### 10. 论文脚本自动同步最新校准参数

`run_paper_simulation.py` 现在在创建论文临时配置时，会先读取：

- `OUTPUT/calibration/calibrated_parameters.yaml`

再把其中的最新参数覆盖到论文专用临时 MFG 配置中。这样可以保证：

- `Paper simulation` 不会继续误用旧版 `CONFIG/mfg_config.yaml` 参数快照；
- 表 4.2 中导出的校准参数，与论文主模拟实际使用的参数保持一致；
- 即使基础配置文件忘记手工更新，论文临时配置仍会优先采用最新校准结果。

若最新校准结果 `success=false`，脚本会输出警告，但仍会同步这份最新参数快照，便于诊断当前结果。

### 11. 论文导表统一绑定“当前这轮运行”的 baseline 与场景集合

本轮进一步修复了三个纯导表层面的口径问题：

- 表 6.2 不再直接使用阶段二 `scenario_baseline` 作为论文基准，而是统一复用阶段一 MFG 基准均衡摘要。这样表 4.4、表 5.2、表 6.2 的 baseline 口径保持一致。
- 表 6.3 不再扫描 `OUTPUT/simulation/` 下所有 `scenario_*` 目录，而是只使用当前 `simulation_results` 中出现的场景名。这样历史残留目录（如旧版 `scenario_training_*`）不会再混入本轮论文表。
- 表 7.1 不再从可能已被后续政策/灵敏度步骤覆盖的 `OUTPUT/mfg/equilibrium_history.csv` 读取基准值，而是直接使用阶段一基准均衡摘要计算百分比变化。

另外，阶段四导表时会重新刷新：

- `OUTPUT/paper_tables/baseline_equilibrium_policy.csv`

确保磁盘上的基准策略快照，与同一轮表 5.2 和表 6.* 实际使用的内存数据一致，方便后续复核。

## 主要调用流程

### 论文主脚本链路

1. `create_paper_mfg_config()` 生成论文专用临时 MFG 配置。
2. `create_shared_population_sample()` 生成共享基础人口样本。
3. `run_baseline_equilibrium()` 在共享样本上求解基准均衡。
4. `run_policy_simulations()` 使用同一共享样本跑全部政策场景。
5. `export_paper_tables()` 统一导出论文表格。

### 单场景模拟链路

1. `MarketSimulator._build_mfg_config()` 基于基准配置生成场景临时配置。
2. `MarketSimulator.run_scenario()` 将场景参数与共享样本传入 `solve_equilibrium()`。
3. `EquilibriumSolver.initialize_population()` 在样本副本上施加场景的人口冲击与初始匹配。
4. MFG 迭代结束后，结果保存到 `OUTPUT/mfg/`，再由场景模块复制到 `OUTPUT/simulation/scenario_xxx/`。

## 输入输出示例

### 输入示例：政策场景配置

`CONFIG/simulator_config.yaml` 中单个场景通常包含：

```yaml
baseline:
  name: 基准场景
  description: 不施加额外政策冲击
  policy_type: none
```

或：

```yaml
A1:
  name: 数字素养提升（中）
  policy_type: training
  population_adjustment:
    mean_D_multiplier: 1.1
```

### 输出示例：政策主表

`OUTPUT/paper_tables/table_6_2_policy_effects.csv` 现在会额外包含：

- `converged`：该场景是否收敛。
- `paper_eligible`：是否满足进入论文主表的稳定性条件。

### 输出示例：矩对比表

`OUTPUT/paper_tables/table_4_4_moment_comparison.csv` 统一包含：

- `moment`
- `target_value`
- `simulated_value`
- `absolute_diff`
- `pct_diff`
- `unit`
- `confidence`

## 验证说明

本次修复完成后，已做两类验证：

1. 编译验证
   - 对四个关键 Python 文件执行 `python -m compileall`
   - 结果通过

2. 小样本冒烟测试
   - 使用缩小版临时配置（`n_individuals=120`、`max_outer_iter=2`）
   - 验证共享样本下培训冲击仍可提高 `S` 均值
   - 验证最终保存结果中就业者 `a_optimal` 的最大值为 `0.0`

## 已知边界

- 当前 `theta` 仍按外生参数处理，尚未改为内生市场紧张度。
- 当前 KFE 中就业者状态变量仍未引入在职演化机制。
- 收敛判定逻辑本身未在本轮重构，仅对论文输出口径做了修复和加固。
